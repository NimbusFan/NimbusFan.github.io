Python 文件 I/O：文本编码、流式处理与持久化

发表于2026-03-18|更新于2026-11-16|Python 技术笔记基础语法与数据结构
|总字数:1.4k|阅读时长:5分钟|浏览量:

文件读写的语法很短，出问题时却经常牵涉三件不同的事：文件中的字节采用什么编码、程序一次加载多少内容、写入失败会留下什么状态。

这里设定一个小任务：读取按行保存的事件记录，统计每个摄像头出现的次数，再生成一份 JSON 汇总。数据只用于演示，不是实际项目的运行记录。示例使用 Python 3.10 及以上版本。

文本模式、二进制模式与字符编码

open(path, "r", encoding="utf-8") 返回文本流，读取时会将字节解码为字符串。open(path, "rb") 返回二进制流，读取结果是 bytes，不执行字符解码。

因此，文本模式下 read(10) 的单位是字符，二进制模式下才是字节。中文字符的个数不能直接当作其 UTF-8 字节数。文件模式和编码参数的完整语义见 Python 的 open 文档。

编码应当与文件实际采用的编码一致。把所有读取都改成 errors="ignore"，可能让程序继续运行，也可能丢掉摄像头标识等有效信息。本例选择严格解码：编码有问题时直接报错，先确认文件来源，再决定是否转换。

事件统计的逐行处理实现

这个实现有几个有意作出的选择：

  • 空行被跳过；其他格式错误会中止统计，错误信息包含文件名和行号。
  • camera 的首尾空白会被移除。如果标识中的空格具有业务意义，就不应采用这一步。
  • 读完并校验全部输入后，才以 w 模式打开输出。输入解析失败时，不会提前清空已有结果。
  • 汇总按键排序，方便比较两次输出；排序不影响计数本身。

程序正常结束后，终端会打印 {'cam-a': 2, 'cam-b': 1}。上面的 JSON 文件则保留缩进和换行，便于人工检查。

迭代读取的内存开销与资源管理

stream.read() 将剩余内容整体读入字符串；stream.readlines() 将剩余各行组织为列表。两者都可能让输入文件的大小直接影响内存占用。

for line in stream 按行迭代，不需要先构造整个文件的列表。但它并不意味着总内存固定：一条特别长的记录仍然会占用较大内存，计数器也会随着不同摄像头的数量增长。本例的内存需求主要取决于最长一行和不同标识的数量。

with 管理文件对象的退出过程，即使循环中抛出异常，也会执行关闭操作。它解决资源释放问题，不会自动吞掉异常，也不会把不完整的业务结果变成有效结果。

缓冲刷新、文件关闭与持久化保证

写入通常经过缓冲。flush() 会将 Python 流的缓冲内容交给底层，不等于已经保证数据写入物理介质。关闭文件会刷新相应缓冲，但也不能据此声称断电后数据一定存在。

对确有持久化要求的文件，可以在 flush() 后调用 os.fsync(stream.fileno())；具体保证仍受操作系统、文件系统和存储设备影响。Python 官方文档明确区分了这两步：os.fsync。

这个例子的另一个边界是：输出阶段采用直接覆盖。如果写到一半发生 I/O 错误，目标文件可能不完整。需要保留上一份结果时，应考虑在同一文件系统写临时文件，再替换目标；是否还需要同步目录项，应按目标平台单独设计。没必要给每个临时统计脚本都加上这一套，但应清楚直接覆盖的代价。

输入校验与失败路径验证

可以做三次小检查：

  1. 插入空行，结果应当不变。
  2. 将第二行改成不完整的 JSON，错误应指出第 2 行，已有的输出不应因输入错误被清空。
  3. 将输入、输出指向同一路径，程序应在打开输出前拒绝操作。

文件处理代码值得检查的地方，往往就在这些失败路径上。成功读出一行，只验证了最顺利的一种情况。
