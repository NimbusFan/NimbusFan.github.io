画图之前，先回答两个问题：输入数据是否满足约定，图中的数量究竟表示什么。否则，一张正常显示的图表，也可能在准确地展示错误结果。

JSON 解析与对象序列化

将下面内容保存为 UTF-8 编码的 camera-counts.json：

文件中保存的是 JSON 文本，解析后得到的是 Python 的列表和字典。两者有对应关系，但并不是同一种东西。JSON 还允许字符串、数字、布尔值和 null 等值，不能将它概括成“一个字典或字典列表”。

json.load(file) 从文件解析，json.loads(text) 从字符串解析；反向操作分别是 dump 和 dumps。这些转换关系见 Python json 文档。

一个常见错误是连续调用两次 dumps：第一次将对象变成 JSON 字符串，第二次序列化的已经是这个字符串，结果会多出一层引号和转义。变量命名为 records、json_text，比反复复用 data 更容易发现类型变化。

类型约束、排序与图形选择

代码用 type(count) is int，有意排除了布尔值。在 Python 中，bool 是 int 的子类，单独使用 isinstance(count, int) 会接受 True 和 False；这里把它们当作计数并不合理。

排序采用“数量降序、标识升序”。前一个规则帮助比较大小，后一个规则让相同数量的记录具有稳定、可解释的排列。不能只排序数量列表而保留原标识顺序，否则会把数值配到错误的摄像头上。

选择柱状图，是因为横轴表示独立类别。把这些摄像头连成折线，容易让人读出并不存在的连续变化。若要分析时间趋势，输入就需要增加时间维度，并明确每个时间桶的统计规则。

统计口径与图表解释范围

这张图可以回答“在同一统计口径下，哪个摄像头记录的事件更多”，不能直接回答“哪个摄像头效果更好”。在线时长、视野范围、去重规则和漏检情况，都可能影响事件数。

这里保留了 cam-d 的零值，以区别“参与统计但结果为零”和“根本没有提供记录”。如果实际系统会缺报，还需要单独表示缺失状态，不能把缺失值直接填成零。

可视化代码最终只有几行配置，真正需要说明的是：数据从哪里来、经过了什么检查，以及读者可以从图中得出多大的结论。
