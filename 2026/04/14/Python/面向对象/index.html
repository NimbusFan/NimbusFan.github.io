Python 对象设计：实例状态、封装与组合

发表于2026-04-14|更新于2026-11-16|Python 技术笔记面向对象程序设计
|总字数:1.4k|阅读时长:5分钟|浏览量:

把几项数据放进一个类很容易，难的是决定：哪些数据属于这个对象，哪些操作允许改变它，调用者应该看到多少内部状态。

这里用一个简化的帧缓冲区讨论这些问题。它只保存摄像头标识和序号，不读取视频，也不是线程安全的生产队列。示例使用 Python 3.10 及以上版本。

帧记录与缓冲区的职责划分

一条帧记录描述“来自哪个摄像头、处于哪个序号”。缓冲区则管理多条记录，还需要控制容量。两者承担不同职责，不必塞进一个不断增加字段的大类。

封装边界、容量约束与快照开销

_frames 的单下划线表示内部实现的使用约定，不是访问控制。调用者仍然能直接修改它，因此接口设计不能靠下划线保证所有行为。

这里通过 append 集中实施容量检查，通过 snapshot 返回一个元组，而不是直接暴露内部列表。拿到快照后再修改缓冲区，不会改变已经返回的元组。

返回元组也有成本：每次需要复制其中的引用，时间和额外空间都与记录数有关。若只需查看数量，用 len(buffer) 就够了。接口应该让这些成本尽量容易判断。

示例在满容量时抛出异常。这适合希望明确发现生产速度超过消费速度的情况。若任务更关注最新画面，可能宁愿丢弃旧记录；若一条记录都不能丢，可能需要阻塞和背压。选择哪一种，应由业务要求决定，不能藏在“缓冲区”这个名称后面。

数据类的值语义与不可变性

dataclass 可以按字段生成初始化、表示和相等比较等方法。frozen=True 限制实例字段的普通赋值，适合这里的简单值记录，但不意味着任意嵌套对象都递归不可变。完整行为见 dataclasses 文档。

Frame("cam-a", 1) == Frame("cam-a", 1) 为真，是因为生成的相等比较按字段值进行。它表达的是本例记录的值语义，不代表两个对象在内存中是同一个实例。

__repr__ 则帮助调试时观察状态。FrameBuffer(capacity=2, size=1) 比默认的对象地址更有用，也没有把可能很大的全部记录都打印出来。

组合、继承与可替换性

FrameBuffer 管理记录，Frame 描述记录，它们通过组合协作。当前没有多种必须互相替换的缓冲区实现，新增一个父类并不能减少实际复杂度。

如果以后出现内存、磁盘等不同后端，可以先明确调用方究竟依赖 append、snapshot 中的哪些语义，再决定采用协议、抽象基类还是普通函数。所谓可替换，不只是方法名相同，还包括满容量、失败和返回值的约定相容。

多线程共享也是新的需求。当前的容量判断和追加没有作为一个同步操作设计，不能直接把这个类交给多个生产线程。需要线程间任务传递时，可以从标准库的 queue.Queue 开始，相关讨论见 线程与任务协作。
