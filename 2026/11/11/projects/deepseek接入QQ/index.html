DeepSeek 接入 QQ：基于 AstrBot 的私聊机器人部署

发表于2026-11-17|更新于2026-11-17|技术实践
|总字数:3.1k|阅读时长:11分钟|浏览量:

最近刷到不少网友把 DeepSeek 接入了 QQ，评论区里调教出来的效果堪比《流浪地球 2》里图恒宇手中的“丫丫”。心血来潮之下，决定在自己的电脑上也折腾一套（ps：我只想给她完整的一生）。

本文记录 Windows 10/11 x64 + 本机 AstrBot + DeepSeek 官方 API + QQ 官方机器人私聊 部署完整实现步骤，并在文末附上已有 NapCat 环境的反向 WebSocket 连接配置，方便按需取用。

2026-11-16 方案说明：早期不少教程依赖 NapCat 挂载普通 QQ 号，但目前 NapCat 上游仓库 已归档停止更新，原文档站也已下线。因此，新部署强烈推荐直接使用本文主线的 QQ 官方机器人方案——合规、支持扫码一键创建、免折腾协议端；如果你手头已经有现成的 NapCat 环境，可以直接跳转文末查看连接配置。

一、原理

可以看到：

  • QQ 开放平台负责消息收发通道；
  • AstrBot 负责对话管理、人格注入和上下文记忆；
  • DeepSeek API 负责云端推理。

二、准备清单与下载入口

开始前需要把软件和账号准备好。因为我们直接用官方启动器 AstrBot Launcher，Python 运行环境会由启动器自动托管，不需要手动安装 Python、Git 或 Docker。

准备项 作用 获取入口 备注
AstrBot Launcher 一键安装、启动、管理 AstrBot 实例 GitHub Releases Windows 常规电脑下载 x64-setup.exe（当前参考版本 v0.3.15），不要下成 Source code
DeepSeek API Key 调用 DeepSeek 模型的凭据 DeepSeek 开放平台 注册后在 API Keys 页面新建密钥，并确保账户内有可用余额（按量计费）
腾讯 QQ & 开放平台 创建官方机器人并扫码绑定 QQ 开放平台 / QQ 官网 用你自己的日常 QQ 扫码创建即可，不会把你的个人 QQ 交给程序托管登录

三、详细实现步骤

安装 AstrBot 并启动 WebUI

  1. 运行下载好的 AstrBot.Launcher_x.x.x_x64-setup.exe 完成安装。
  2. 打开启动器，点击创建实例：
    • 实例名称：比如 qq-deepseek；
    • 安装目录：选一个普通用户有读写权限的短路径，例如 D:\Apps\AstrBot；
    • 核心版本：选择当前最新稳定版。
  3. 点击启动实例。首次启动会自动下载 Python 环境与核心依赖，耐心等待控制台日志跑完。

    避坑提示：如果首次拉取依赖中途因网络超时失败，先看日志里卡在哪个包，调整网络或下载源后重试，不需要反复卸载重装启动器。

  4. 启动成功后，在浏览器打开默认管理后台：
  5. 登录后台：默认用户名是 astrbot，初始密码是随机生成的，需要从启动器的运行日志里复制。登录后按提示修改为你自己的管理员密码。

(整个流程由 AstrBot 主动通过 WebSocket 连接 QQ 平台，因此 6185 端口只需保留本地访问，不要把后台映射到公网。)

  2. 选择 DeepSeek（如果当前版本没有内置模板，选 OpenAI Compatible 通用兼容接口即可），按如下参数填写：

绑定默认配置文件

在 AstrBot 里，“添加模型”只是把模型放进仓库，还需要告诉机器人“实际聊天时用哪一个”：

  1. 进入 「配置文件」，打开正在使用的配置（默认为 default）。
  2. 确认开启 AstrBot 内置 AI，并在 「AI → 模型」 下拉框中选中刚才添加的 deepseek-official / deepseek-flash。
  3. 检查 「平台与消息」 与访问控制，确保私聊触发已开启，且没有把自己误关在白名单之外。
  4. 点击保存。首轮测试不要装第三方插件，保持最纯净的纯文本链路。

扫码创建并绑定 QQ 官方机器人

参考 AstrBot QQ WebSocket 文档：

  1. 在 WebUI 左侧打开 「机器人 → 创建机器人」。
  2. 适配器类型选择 QQ 官方机器人（WebSocket），创建方式选 「扫码一键创建」。
  3. 掏出手机 QQ 扫描屏幕上的二维码，在手机端确认授权创建。
  4. 稍等几秒，后台会自动帮你申请并回填 AppID 和 AppSecret。
  5. 关键检查：在机器人配置项中，确认勾选了 “启用消息列表单聊”（enable_group_c2c），否则只能进频道私信，无法在普通 QQ 消息列表里像好友一样直接聊天。
  6. 启用并保存该机器人实例。

(如果当前版本未显示扫码入口，也可以自己登录 QQ 开放平台 创建一个机器人，把后台的 AppID 和 AppSecret 复制填进来，效果完全一致。另外，如果平台要求配置 IP 白名单，填写电脑当前的出口公网 IP 即可。)

四、调教：让她更有“人味”

链路跑通后，就可以开始打磨体验，把大肥鱼变成流浪地球2中图恒宇的丫丫。

1. 写一份人格 Prompt

不要上来就堆砌几千字，指令越多模型越容易精神分裂。在 WebUI 的 「人格设定」 中新建一个人格（例如 dafeiyu），可以从下面这套简洁的骨架开始微调：

保存后，记得回到「配置文件」里把默认人格切换成新建的这个，然后直接在 QQ 里发送指令 /new 开启新对话即可生效（/reset 则可以随时清空当前对话上下文）。

2. 回复节奏与群聊扩展

  • 避免盲目按字数截断：不要设置“超过 60 字强制截断”，否则遇到解释技术问题或发代码时会把代码块腰斩。保持关闭人为打字延迟和强制分段，等稳定运行几天后再按需微调。
  • 拉进群聊：如果想把她拉进亲友群，先在配置里把群聊触发策略设为 “仅 @机器人 时回复”。注意在 QQ 里必须通过弹出的成员列表真正 @ 到她（原生提及事件），手动打字输入 @大肥鱼 是不会触发回复的。

五、常见问题

如果遇到机器人“装死”或报错，前往 AstrBot 的 「数据与日志」：

1. QQ 收发与触发异常

现象 排查方向
扫码后在 QQ 里找不到聊天入口 检查是否扫了机器人详情页的「聊天二维码」，以及个人 QQ 是否在平台的测试成员名单中
QQ 发了消息，但 AstrBot 日志毫无反应 检查官方机器人实例是否已启用、“启用消息列表单聊” 是否勾选、AppID/AppSecret 是否正确
日志收到了消息事件，但没有调用模型 检查是否误开了白名单/黑名单拦截、AI 总开关是否打开，或机器人绑定的配置文件选错了
发一条消息收到两条一模一样的回复 检查电脑后台是否同时开了两个 AstrBot 实例，或重复绑定了同一个机器人

2. DeepSeek 接口报错

HTTP 状态码 原因与解决方法
400 / 422 请求参数格式有误，检查模型 ID 是否拼错，或 extra_body JSON 括号是否闭合
401 API Key 无效、过期，或者复制时多带了空格
402 DeepSeek 账户余额已用完，去控制台充值即可
429 请求频率触发限流，稍等片刻或关闭频繁重试
连接超时 检查本机代理/VPN 设置是否干扰了直连 api.deepseek.com

六、附录：已有 NapCat 环境的反向 WebSocket 配置

如果使用场景必须用普通 QQ 账号以“好友”身份聊天，且手头已经有能正常运行的 NapCat（可参考社区归档 v4.18.42），可以通过 OneBot v11 反向 WebSocket 将它接入 AstrBot。

连接方向与官方机器人相反——由 AstrBot 监听本地端口，NapCat 主动连过来：

配置步骤（以两端同在一台 Windows 电脑为例）：

  1. AstrBot 侧：进入「机器人 → 创建机器人」，选择 OneBot v11：
    • 反向 WebSocket 主机地址：127.0.0.1
    • 反向 WebSocket 端口：6199
    • 反向 WebSocket Token：自己随便编一串复杂字符（例如 my_secret_token_6199）
    • 启用并保存。
  2. NapCat 侧：从 NapCat 启动日志找到它的 WebUI 地址（默认通常是 http://127.0.0.1:6099）并登录，在 「网络配置」 中新建 WebSocket 客户端：
    • URL：ws://127.0.0.1:6199/ws
    • 消息格式：array
    • Token：填写与上面完全一致的 my_secret_token_6199
    • 启用并保存。

注意区分三个端口：6185 是 AstrBot 后台，6099 是 NapCat 后台，6199 才是两者的通信端口；如果两者分别跑在 Docker 容器和宿主机里，记得把 127.0.0.1 换成对应的容器网络地址或宿主机网关 IP。

因为机器人跑在个人电脑上，合上笔记本盖子、系统休眠或断网都会导致掉线。如果打算长期挂机，记得在 Windows 电源选项里关闭自动休眠，并定期通过启动器备份实例目录（备份前先正常停止实例，防止 SQLite 数据库损坏）。
